Histórico

Nova transferência

Uma transferência entre regiões é uma transacção distribuída com Two-Phase Commit: os dois nós preparam (PREPARE TRANSACTION), o coordenador grava a decisão e só depois confirma.

Percurso da transacção distribuída

Faça uma transferência para ver o protocolo 2PC passo a passo.

Estado de cada transferência no registo do coordenador e de cada participante. Durante uma falha (por exemplo docker compose stop db-america) uma transferência pode ficar COMMIT_DECIDIDO e concluir sozinha quando o nó voltar.

Os extractos e a auditoria ficam no sistema de ficheiros distribuído (NFSv4), montado em /mnt/dfs nas duas APIs e no coordenador. Um relatório escrito pela api-1 é lido pela api-2 sem saber em que máquina está o disco (transparência de localização).

Conteúdo

Escolha um relatório.

Cada componente é verificado pela instância da API que está a responder. Derrube um nó na demonstração (docker compose stop …) e veja-o ficar vermelho; ao arrancar de novo volta a verde.

Token JWT (RS256)

Emitido pelo nó auth com a chave privada. A API verifica a assinatura, exp, iss e aud com a chave pública, sem contactar o emissor.

Ordem de transferência assinada

Os campos da ordem são postos em JSON canónico, resumidos com SHA-256 e assinados com RSA-PSS pela chave privada da instância. O coordenador verifica a assinatura antes de alterar qualquer saldo; um montante adulterado é recusado (HTTP 401).

Faça uma transferência para ver o resumo SHA-256 da ordem assinada.

Medidas activas

  • TLS/HTTPS em todos os serviços Web e TLS verify-full nas ligações ao PostgreSQL
  • Palavras-passe com scrypt e sal aleatório
  • Autorização: só o titular consulta ou movimenta a conta
  • Janela de 120 s e chave de idempotência contra repetições
  • Segredos fora do repositório (Docker secrets)
